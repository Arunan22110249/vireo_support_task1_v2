# Vireo Audio — Support Ticket Categorisation (Task 1 V2)

## What this does
A small, reproducible AI-assisted support-ticket categoriser and reporting tool.

It:
1. restricts analysis to Jan 2025–Jun 2026 as specified in the brief;
2. combines the customer's opening message with the agent's closing note;
3. trains a TF-IDF + Linear SVM text classifier on Vireo's existing category tags;
4. produces an AI category alongside the original intake tag;
5. generates monthly category/team CSVs and charts;
6. runs a validation report (`data_quality.csv`, `team_summary.csv`, `validation_summary.md`), all regenerated by `app.py` on every run.

## Run from a clean machine

Requires Python 3.10+.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python app.py --data-dir data --output-dir outputs
```

Expected input files:
- tickets.csv
- agents.csv
- customers.csv
- orders.csv
- products.csv

The support-policy.pdf and email-thread.txt are context documents; the analysis decisions are recorded in `memo/` and `submission/`.

One exception: `outputs/manual_audit_66.csv` is a **static, human-labeled file** (66 tickets manually reviewed against the model's predictions). It is not, and cannot be, regenerated by `app.py` — it is checked in as evidence. If present, `app.py` reads it to compute the agreement rate in `validation_summary.md`; if absent, the script still runs and notes that the audit file was not found.


## Important modelling decision
The historical category is a noisy intake-bot tag, so it is used as a training signal, not treated as ground truth. The repository includes:
- 5-fold cross-validation against historical tags;
- a 66-ticket stratified manual audit;
- an explicit data-quality report.

The manual audit is the more useful correctness check, but it is still a model-assisted human review rather than an independently adjudicated gold set.

## Key business finding
For the stated 18-month window:
- 11,641 tickets.
- Billing is 2,425 tickets (20.8%).
- Logistics is 1,905 tickets (16.4%).
- Billing also has the highest first-response breach rate at 19.7%.
- 477 Billing tickets breached SLA, creating Rs 166,950 in SLA credits.
- 632 Billing transfers are recorded where the transfers field exists, costing Rs 192,760 at the policy rate.

The analysis does **not** recommend treating ticket volume as sufficient evidence for two hires. The data supports prioritising Billing for investigation, but process/routing fixes should be tested against the Rs 9 lakh/year cost of two hires before committing.

## Known limitations
- Historical labels are noisy and the classifier learns from them.
- The manual audit is only 66 tickets.
- Some legacy rows have no transfer count.
- Some resolution timestamps produce negative handle times; those are excluded from staffing-cost calculations.
- No attempt is made to infer staffing capacity from handle time because the source data is not reliable enough for that purpose.
